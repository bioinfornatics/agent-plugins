# Feedback Annotation Contract 1.0.0

This contract records review feedback without mutating the reviewed object. An annotation binds one product, scenario, output, grade, or rectangular region at an exact revision and SHA-256 resource hash. Reviewer identity, UTC timestamp, and instruction are mandatory. The annotation is content-addressed and immutable.

Interpretation is a separate, content-addressed artifact. It records intent, closed JSON Pointer patch operations, affected resources, and required tests. A proposal binds the annotation and interpretation and its `baseResourceId`, `baseRevision`, and `baseHash` must exactly equal all three fields of the annotation anchor. `correct` supplies replacement operations while `reject` supplies none. Constructors clone a closed input and write the contract version after removing caller-supplied version/hash fields, so runtime callers cannot override constants despite TypeScript erasure.

Preview applies operations only to an isolated JSON snapshot and hashes the complete exact before/after plan. Decision requires the current revision, current resource hash, proposal hash, preview hash, and the original annotation and interpretation. It independently validates and recomputes every hash and binding in annotation → interpretation → proposal → preview; merely recomputing hashes on forged objects is not sufficient without the original provenance chain. Any mismatch fails closed. Acceptance creates revision `n + 1` for candidate/scenario resources with complete provenance. The prior value is never changed.

The dependency input is a complete graph rooted at the revised resource: resource IDs are unique, every dependency reference exists, every declared node is reachable from the root, and cycle detection runs over every node, including disconnected components before reachability rejection. Direct dependants require rerun and transitive dependants are invalidated. Every effect explicitly binds `sourceResourceId`, the new `sourceRevision`, and its `sourceHash`. Each proposal `requiredTests` entry also becomes a `test`/`rerun-required` effect bound to that same new revision. Rejection is a hashed, auditable decision and creates no revision.

All objects are closed plain JSON data. Accessors, proxies, exotic prototypes, sparse arrays, duplicate IDs, forbidden prototype paths, non-finite numbers, malformed hashes/timestamps, unknown fields, and oversized values are rejected. Hashes use canonical JSON with lexically sorted object keys. Comparisons verify stored hashes before reporting a diff.
