# Producer Inventory Specification

The result compatibility inventory is maintained in fixtures/result/producer-inventory.json. It is acceptance evidence, not a second runtime output format.

## Current producer definitions

Each current entry records the emitting creator, repository-relative sourceFile, exact output field, mapping context, complete current tokens, and exact sourceEvidence. A multi-file producer additionally lists sourceFiles; its snippets must be found across that closed list. Contract tests read those producer files directly and require exported mapping triples to equal the fixture exactly.

The inventory covers finite categorical fields, process exits, and booleans that independently communicate operation, evaluation, evidence, approval, or release-eligibility semantics. Thus verification receipt top-level status, ValidationOutcome.status, ComponentOutcome.status, trigger/grading verdict booleans, and release_eligible are included. ValidationOutcome.status is limited to accepted, rejected, and partial; component-only skipped variants and runtime-failed use the distinct plugin-component-outcome-status context.

Two autonomous aggregate/document boolean pairs were added by the ap-rcj.1.3.6 remediation: `plugin-schema-aggregate-valid` (SchemaValidationResult.valid, every document valid) with its own `plugin-schema-document-valid` (per-document DocumentResult.valid), and `plugin-mcp-aggregate-valid` (McpSemanticResult.valid, every server valid) with its sibling `plugin-mcp-aggregate-policy-valid` (McpSemanticResult.policyValid, every server policy-valid). Each aggregate is an autonomous true/false pass/fail signal derived directly from an `Array.every` over independently emitted per-item booleans; it is current, not copied, because no other context already carries that exact aggregate meaning.

## Copied and nested fields

copiedNestedFields includes emitted nested fields that independently expose categorical status to a consumer but copy an already inventoried producer value without changing its meaning. They reuse the named canonical context rather than duplicating mappings. This covers plugin component receipt statuses, plugin full-eval nested verification receipt, the skill verification receipt nested authoring audit, and skill full-eval nested audit/design/receipt/verification results. Tests require every alias snippet and canonical context to exist.

copiedNestedFields also now includes McpServerSemanticResult.valid and .policyValid (per-server booleans aliasing plugin-mcp-aggregate-valid / plugin-mcp-aggregate-policy-valid through Array.every), skill-creator's run_loop.ts `history[].train_results[].pass`, `history[].test_results[].pass`, and the legacy fallback `history[].results[].pass` (all aliasing skill-trigger-result-pass; `results` is the backward-compatible field consumed via `first.train_results ?? first.results` in generate_report.ts), improve_description.ts `HistoryEntry.results[].pass` rendered as PASS/FAIL text (also aliasing skill-trigger-result-pass), and plugin-creator's CLI `validate` command forwarding `outcome.status` into `ok` (aliasing plugin-validation-outcome).

Structural booleans such as dry_run, resume, component receipt available, and migration blocking, plus numeric counts, rates, thresholds, and duplicated numeric exit summaries, do not independently state a result-contract axis. They are listed in excludedStructuralFields with rationale. A copied field that transforms meaning or introduces a new finite domain must instead become a current mapping context. PathContainmentResult.contained and .kindOutcome are excluded for the same reason: `status` is the canonical, already-mapped containment outcome (plugin-path-containment-status); `contained` is a redundant boolean projection of `status`, and `kindOutcome` is a filesystem-kind observation (expected-vs-actual file/directory match), not an operation, evaluation, evidence, or approval axis.

## Non-current vocabulary

documentedNonCurrent records vocabulary that is type-only, fixture-only, rendered text, or historical shorthand rather than a currently emitted value of the named field. Top-level and component validation exclusions are separate. policy-failed is type-only for both validation fields; packaged is not emitted as a status field; MCP legacy-compatible is type-only and not returned. In contrast, migration finding legacy-compatible is current because migrate_plugin.ts emits it for unknown manifest fields and runtime-specific support artifacts.

Those non-current tokens must be absent from LEGACY_STATUS_MAPPINGS. A future producer branch must first move a token into current with exact source evidence and add a contextual mapping. Boolean fields use exact true/false string tokens accepted by mapLegacyStatus; process exits use decimal strings. Inventory provenance does not authenticate producer identity or authorize approval.

The bounded tests use independently maintained exact producer expectations for receipt status, full-eval forwarding, validation field separation, and challenged non-current branches. A general AST-derived producer manifest would improve future discovery but is deferred; it is not required for this correction because exact audited snippets and negative branches are regression-locked.

## Independent expectedConsumerFields completeness contract

fixtures/result/expected-consumer-fields.json is maintained independently of producer-inventory.json: it is derived directly from reading each producer source file, not copied from the inventory's own entries. It lists at least 13 stable-id records covering the schema aggregate/document valid pair, the MCP aggregate/server valid and policyValid pairs, PathContainmentResult.contained/kindOutcome, the run_loop train/test/fallback results[].pass aliases, the improve_description history results[].pass alias, and the plugin CLI outcome.status alias. Each record states its creator, sourceFile, exact field, sourceEvidence, and classification (current, copied, or excluded), plus a context (current), canonicalContext (copied), or rationale (excluded/current). A dedicated test loads this fixture and asserts every record's classification and, where applicable, its context or canonicalContext is present in the exact union of producer-inventory.json's current mappings, copiedNestedFields aliases, and excludedStructuralFields — with no duplicate or missing IDs and every sourceEvidence snippet verified against the named source file independently of producer-inventory.json's own snippets.
