# Evaluation preparation protocol

This is execution governance and proof guidance, not a setup hook, task tracker or
campaign authorization. The evaluator copies declared `files` bytes into both
arms at identical relative paths. Private HOME/XDG is not an OS sandbox.

## Frozen task inputs and equivalent arms

- All nine cases declare neutral task data under `evals/inputs`. No task data
  depends on treatment installation. `SKILL.md.fixture` remains inert during
  capture; no reserved entrypoints, discovery roots, credentials, symlinks or
  config.yaml are declared inputs.
- Review cases 2, 4, 5 and 9 inspect drafts directly. Case 1 uses a brief; case 8
  uses an installation request. Case 3 migrates to a new output package.
- Cases 6 and 7 explicitly request preparation **from the supplied drafts**.
  The task agent creates canonical package entrypoints as part of the requested
  deliverable. Case 6 produces deliverables/notes-package.zip; case 7 creates
  deliverables/comparison and observes its dry-run. There is no assumed root
  `package`/`comparison` directory and no hidden external pre-trial preparation.
- Source fixtures remain unchanged. Generated destinations must be new and local
  to the trial workspace; outputs are not installed into live discovery roots.
  Criteria and proof oracles remain outside prompts; do not inject rename steps,
  commands, expected counts or answers into task requests.

## Equivalent-tooling gate

Before any authorized campaign, verify both arms receive equivalent approved
filesystem/archive tools, output permissions and independently available current
skill-creator guidance/contained launcher. Freeze input identity, model settings,
turn/time limits, repetitions, stopping rule and permitted effects separately.
The suite does not install that launcher or supply a setup mechanism. Availability
in this authoring checkout does not prove both-arm availability in native trials.
If unavailable, record the precise blocker and missing evidence, not a pass from
an accurately proposed command. Case 8 also needs current official/repository
source access for verified installation guidance.

## Proof boundaries

Suite dry-run proves import and matrix preparation without model calls; it does
not perform either task or prove archive delivery, native tooling equivalence or
behavioral effectiveness. A deterministic local temporary-copy check may test
neutral draft materialization and nested dry-run discovery when expressly allowed.
That is a public-seam fixture check, not hidden campaign prep or candidate behavior.
Compare complete inventories, bytes and permission bits, and preserve input hashes.

No models, grading, retries, Git/tracker changes, credentials, live installation or
publication are authorized by this rewrite. Future campaign execution needs
separate authority. Grade actual artifacts/tool events and independent semantic
review, never just task self-reports. Equivalent tooling in both arms remains an
explicit unverified gate even after successful local deterministic checks.
