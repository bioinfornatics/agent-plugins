# Non-interactive CI evaluation

`plugin-creator ci-eval --config FILE --format json` is the clean-checkout CI entry point. **Use the shipped native executable**: consumer CI must not run `npm ci`, compile TypeScript, or install development dependencies. The provider-neutral host receives `preflight --request FILE` and, only after a ready preflight, `full_eval --request FILE`. Each command emits exactly one JSON object. Preflight emits `{"status":"ready","capabilities":[],"models":[]}`; full evaluation emits `{"status":"pass"}`. No browser or prompt is available (stdin is closed and `PLUGIN_CREATOR_NON_INTERACTIVE=1`). The Goose reference job and adapter are under `templates/ci/`.

Configuration is closed and strictly typed: unknown keys, wrong optional/nested types, invalid enum values, non-finite/out-of-range numbers, duplicate/empty list entries, unsafe paths, and invalid cross-field combinations exit `2` before any output directory is created or host subprocess starts. Paths are checkout-relative; the plugin must exist inside the checkout; the workspace must be below `plugin_path/evaluations/`; integration and package archive paths must be inside that workspace. Symlinks, junction escapes, and unsupported evidence entries are rejected.

Credentials are environment-variable names in `host.required_credentials`. Non-secret host variables are names in the `host.environment` allowlist; only listed names are copied from the parent environment. The shipped Goose config explicitly forwards `GOOSE_CI_VERIFIED_MODELS`, `GOOSE_PROVIDER`, and `GOOSE_MODEL`, while `PROVIDER_API_KEY` remains a required credential. Missing credentials, models, or capabilities stop before evaluation. Secret values must not appear in config or arguments. Declared credential values and common credential patterns are redacted from host reasons, stdout, stderr, errors, transcripts, cached results, and command output regardless of transcript policy.

Limits bound each host subprocess, captured output, full-eval budget, and archived evidence size. Exit codes are `0` success, `1` evaluation failure, `2` invalid configuration, `3` blocked capability/evidence, and `4` evidence-complete pending human approval. The final outcome is derived from full-eval jobs and verified receipts/benchmark/archive evidence, never from the host's claimed outcome alone.

The archive contains guidance, a manifest, selected sanitized evidence, and transcripts according to `privacy.transcripts` (`omit`, `redact`, or `include`; include does not disable secret redaction). By default it selects `full-eval-events.jsonl`, `**/benchmark.json`, `**/review.html`, and `**/receipt.json`. `privacy.archive_globs` replaces this list. Its portable allowlist supports literal path segments, `?`, `*` within a segment, and `**` across segments; absolute paths, backslashes, `.`, `..`, character classes, braces, extglobs/negation, more than 64 patterns, and overly complex patterns are rejected. Selection is bounded to 1,024 files, each no larger than `limits.max_output_bytes`.

`inventory.json` records every other archive file's relative path, SHA-256, and byte count. Cache reuse authenticates the config hash, plugin hash, result hash, archive path, inventory-file hash, exact inventory equality/completeness, every listed file hash and size, and a result outcome re-derived from bound full-eval evidence. Missing, extra, forged, stale, symlinked, or tampered evidence causes a fresh run.

For offline CI, use an installed host adapter or a local fake and require no remote model. Use the native `skills/plugin-creator/scripts/plugin-creator` executable injected into the staged release; the portable source Skill contains no vendored runtime. Network availability is never inferred as capability readiness.

## Shipped-template closure evidence

`apps/plugin-creator-cli/tests/test_ci_templates_contract.test.ts` is the source-development release contract for the documented templates. It verifies the canonical template modes and runs both the provider-neutral host protocol and shipped Goose adapter offline with deterministic local fakes. Consumer CI uses the staged native executable and must not run `npm install` or a build. The expected terminal result remains exit `4` / `pending-approval`. This test is the closure evidence for `ap-rcj.6.2`.
