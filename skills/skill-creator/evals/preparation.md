# Preparation protocol

This is setup guidance, not candidate instructions, task tracking or execution
acceptance. No model campaign, resume or paid grading is authorized by this change.
See [coverage](coverage.md) and [active suite](evals.json).

## Both-arm equivalence

`files` captures neutral Skill-root-relative bytes and copies them at identical
paths in both arms. Inert `SKILL.md.fixture` drafts are task data, not discovery
entrypoints. No treatment launcher, materializer, SKILL.md or AGENTS.md is declared
as input. The harness must expose current operational CLI/report capabilities
identically to both arms; instructions from the selected Skill remain treatment.

Record prepared workspace/input hashes, source identity, tools, configured default
model (omit overrides), limits and stopping rule before any authorized run. There
is no per-case setup hook or supported custom constraint enforcement. Authoring
and report tasks require writable destinations and filesystem/shell access. Current
contained CLI/helper execution requires Node >=22.22.2. Missing equal operational
tooling blocks an execution criterion; it is not a baseline quality failure.

## Actual draft preparation: cases 6–7

The user requests preparing drafts, which authorizes creating active entrypoints
in **new output folders**. This is a product authoring task, not evaluator-policy
text. Candidates read the supplied inert drafts, author new SKILL.md files, preserve
exact suites (and case 7's supplied canonical manifest), and invoke the current CLI
with --dry-run against the canonical **new active roots**. The source paths remain
unchanged. No evaluator materialization is needed or falsely presumed.

Case 6 expects one scenario/six planned runs; case 7 combines the new Plugin root
and its included action-list root, expecting two scenarios/twelve planned runs and
one deduplicated whole-Plugin component. Successful CLI JSON and exit status are
required; a proposed command does not pass. No nested model/grade calls are allowed.
These matrices establish preparation only, not quality or host/model compatibility.

not active procedural substitutes. Bind their tokens only from an operator-verified

The inspected app tests build fixtures through public storage seams in temporary

and evidence are present, archive verification succeeds, and read-only commands

explicit later model authority; completed work must remain intact. Grading requires
valid completed attempts and separate later paid authority. Export must reverify
archives and use explicit decisive grades and a new destination. No such fixture
was generated here; historical workspaces/report exports do not substitute.
