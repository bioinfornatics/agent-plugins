# Verification gates

Generate a skill receipt with `skill-creator verify`.

Gate states are `pass`, `fail`, `blocked`, or `na`. A required `fail` makes the artifact fail. Any other required gate that is not `pass` makes it blocked. Gate, profile, and human-review values are validated at runtime; unknown values are rejected rather than treated as passing evidence.

Profiles:

- `static`: structure and portability.
- `evaluation`: static gates, tests, paired behavior, and review.
- `release`: evaluation gates plus triggering and overlap verification.

Behavior must pass both the absolute pass-rate threshold and the minimum baseline delta. Pass rates must be finite numbers in `[0,1]`. A positive delta alone is insufficient.

Behavioral evidence is source-bound. Put the SHA-256 returned as the receipt's `source_sha256` into `benchmark.json` as `metadata.source_sha256` when the benchmark is produced. A mismatch fails the behavior gate. Missing provenance blocks evaluation and release receipts, so an unbound benchmark can never make a release pass.

Evaluation workspaces may use either layout:

- `eval-N/<configuration>/run-N/{outputs,grading.json,timing.json}` (multi-run), or
- `runs/eval-N/<configuration>/{outputs,grading.json,timing.json}` (legacy single-run).

A plugin receipt is generated by `plugin-creator verify`. It consumes one current skill receipt per bundled skill, rejects stale hashes, and adds identity, integration, distribution, regression, and review gates. `release_eligible` is true only when every required gate passes.
